## Summary

本 Issue 报告了 v2 架构下 input_file 与 flusher_http 组合使用时的转换器兼容性问题（unsupported event type 3）。经核对 Epic #2595 进度与当前 main 代码，该报错符合 v2 Pipeline 演进阶段的已知限制：C++ Native Input 在 v2 下产出的事件类型（PipelineEventGroup，type 3）尚未被 flusher_http 的 Converter 完整适配。Epic 中 B3/B4/C1 等步骤仍在推进中，当前 main 尚未合并相关修复。属于真实缺陷与核心能力缺口，故保持开启。

## Best Possible Solution

维护者应将本 Issue 关联至 Epic #2595。待 B3/B4/C1 步骤（扩展 Flusher/Processor 对多事件类型支持及 CGO SendPipelineEventGroup）合并后，验证 flusher_http 对 event type 3 的转换支持。短期内建议在本 Issue 回复已知限制说明，并提供临时 Workaround（如暂使用 StructureType: v1，或改用已适配 v2 的 flusher_sls/flusher_stdout 验证链路）。后续需补充 flusher_http Converter 对 PipelineEventGroup 的 raw/custom 编码逻辑及 E2E 测试。

## Evidence

- **epic_tracking:** Epic #2595 明确跟踪 Native Input 与 Go 插件打通工作，当前 B3/B4/C1 步骤（扩展 Flusher/Processor 对多事件类型支持）仍为开放状态，PR #2620 亦声明不保证运行时数据可达。
- **error_source:** 报错 unsupported event type 3 源自 flusher_http 转换器对 v2 新事件类型（PipelineEventGroup）的 switch/default 分支，当前 main 尚未包含对该类型的 raw/custom 协议转换实现。
