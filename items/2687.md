## Summary

本 Issue 报告了 v2 架构下 native input_file 与 Go flusher_http 组合运行时，Converter 阶段抛出 unsupported event type 3 导致日志丢弃的真实缺陷。该现象与 Epic #2595 规划的 Native Input → Go 插件桥接演进路线直接相关，属于已知架构过渡期的运行时限制。

## Best Possible Solution

保持开启并关联至 Epic #2595 作为 v2 Native→Go 运行时桥接的验证用例。建议维护者在 B3 (Extended Flusher 补齐 FlusherV2.Export) 或 C1 (CGO SendPipelineEventGroup) 阶段优先覆盖 flusher_http 的 raw/custom 转换路径。临时 workaround 可建议用户回退至 StructureType: v1 或改用 flusher_sls 等已完整适配 v2 的组件。待相关 PR 合并后验证关闭。

## Evidence

- **epic_tracking:** Epic #2595 明确规划了 v2 Pipeline 演进路线，当前处于阶段 1/2。B3 与 C1 步骤尚未完成，FlusherV2.Export 与 CGO 事件桥接逻辑仍在开发中，直接导致多事件类型（如 type 3）在 Go 插件侧无法正确转换。
- **pr_disclaimer:** 已合并的 PR #2620 (A1) 正文已明确声明「不保证 Parse 成功 = 运行时数据可达」，证实配置解析放行后，运行时数据链路打通仍需后续步骤补齐，本 Issue 为该预期缺口的实际复现。
- **repro_logs:** 用户提供最小复现配置与 go_plugin.LOG 报错 unsupported event type 3，确认 flusher_http 的 Converter 在当前 main 上尚未适配 v2 native input 产出的特定事件类型，属于可挽救的真实缺陷。
