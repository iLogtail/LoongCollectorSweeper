## Summary

本 Issue 报告了 v2 架构下 input_file 与 flusher_http 组合使用时，Converter 未适配 v2 新事件类型（Type 3）导致日志丢弃的核心链路问题。经核对 Epic #2595 进度，相关 Flusher/Processor 对 v2 多事件类型的适配工作（B3/B4/C1 步骤）仍在进行中，属于已知的核心能力缺口，非插件生态或仓库外事务，且复现路径清晰，故保持开启。

## Best Possible Solution

保持开启并关联至 Epic #2595。维护者应在 B3/B4 演进步骤中补齐 flusher_http Converter 对 v2 事件类型（Type 3）的 raw/custom 协议转换支持。短期内建议在本 Issue 回复已知限制说明，并提供临时 Workaround（如暂使用 StructureType: v1，或改用已适配 v2 的 flusher_sls/flusher_stdout 验证链路）。后续需补充对应 E2E 测试与转换逻辑。

## Evidence

- **epic_tracking:** Epic #2595 明确跟踪 Native Input 与 Go 插件打通工作，当前 B3/B4/C1 步骤（Extended Flusher 补齐、Processor 迁移、CGO SendPipelineEventGroup）仍为开放状态，尚未完成 flusher_http 对 v2 新事件类型的完整适配。
- **error_source:** 报错 unsupported event type 3 源自 flusher_http 转换器对 v2 新事件类型的 switch/default 分支，当前 main 尚未包含对该类型的 raw/custom 协议转换实现。
