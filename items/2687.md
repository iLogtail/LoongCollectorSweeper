## Summary

本 Issue 报告了 v2 架构下 native input_file 与 Go flusher_http 组合运行时，Converter 阶段抛出 unsupported event type 3 导致日志丢弃的缺陷。该问题与 Epic #2595 规划的 Native Input → Go 插件桥接演进路线直接相关，属于架构过渡期的已知运行时限制。PR #2620 (A1) 已明确声明不保证 Parse 成功即运行时数据可达，当前 B3/C1 步骤仍在推进中，Go 插件侧对 v2 多事件类型的转换支持尚未完全补齐。

## Best Possible Solution

保持开启并关联至 Epic #2595 作为 v2 Native→Go 运行时桥接的验证用例。建议维护者在完成 B3 (Extended Flusher 补齐) 或 C1 (CGO SendPipelineEventGroup) 阶段后验证修复。临时 workaround 可建议用户回退至 StructureType: v1 或改用已完整适配 v2 的 flusher_sls 等组件。待相关演进 PR 合并且转换链路打通后关闭。

## Evidence

- **epic_tracking:** Epic #2595 明确规划了 v2 Pipeline 演进路线，当前 B3 与 C1 步骤尚未完全闭环，FlusherV2.Export 与 CGO 事件桥接逻辑仍在开发中，导致 Go 插件侧无法正确转换 native input 产出的特定事件类型（如 type 3）。
- **pr_disclaimer:** 已合并的 PR #2620 (A1) 正文声明「行为变更：无...不保证 Parse 成功 = 运行时数据可达」，证实配置解析放行后，运行时数据链路打通仍需后续步骤补齐，本 Issue 为该预期缺口的实际复现。
- **repro_logs:** 用户提供最小复现配置与 go_plugin.LOG 报错 unsupported event type 3，确认 flusher_http 的 Converter 在当前 main 上尚未适配 v2 native input 产出的特定事件类型，属于可挽救的真实缺陷。
