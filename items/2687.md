## Summary

本 Issue 报告了 v2 架构下 native input_file 与 Go flusher_http 组合运行时，Convert 阶段抛出 unsupported event type 3 导致日志丢弃的问题。该现象与 Epic #2595 主线 A/B/C 的演进目标直接相关，PR #2620 (A1) 已明确说明仅放开配置解析限制，不保证运行时数据可达。当前 v2 桥接层与 Go 插件 Converter 对多事件类型（尤其是类型 3）的适配仍在进行中，属于已知架构演进过程中的真实缺陷/限制，需等待后续 B3/C1 等步骤补齐 FlusherV2.Export 与事件转换逻辑。

## Best Possible Solution

保持开启并关联至 Epic #2595 作为 v2 Native→Go 运行时桥接的验证用例。建议维护者在 B3 (Extended Flusher 补齐 FlusherV2.Export) 或 C1 (CGO SendPipelineEventGroup) 阶段优先覆盖 flusher_http 的 raw/custom 转换路径。临时 workaround 可建议用户回退至 StructureType: v1 或改用 flusher_sls 等已完整适配 v2 的组件。待相关 PR 合并后验证关闭。

## Evidence

- **epic_tracking:** Epic #2595 明确规划 Native Input → Go 插件的 v2 桥接演进，当前处于阶段 1/2，PR #2620 (A1) 正文已声明「不保证 Parse 成功 = 运行时数据可达」，本 Issue 为该演进路线中的预期运行时缺口。
