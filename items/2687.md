## Summary

本 Issue 报告了 v2 架构下 flusher_http 转换器未适配多事件类型（event type 3）导致日志丢弃的真实缺陷。该问题与 Epic #2595 阶段 2 待办项（B4/B5）高度吻合，属于已知架构演进路线中的核心兼容性问题，需保持开启以跟踪修复进度。

## Best Possible Solution

保持开启并关联至 Epic #2595。维护者需在阶段 2 步骤 B4/B5 中为 flusher_http 的 Converter 补齐对 v2 PipelineEventGroup 多事件类型的解析与转换逻辑。修复发布前，可建议用户临时使用 StructureType: v1 或移除 Convert 配置段以绕过数据丢弃问题。后续需补充 v2 模式下 HTTP flusher 的 E2E 测试验证。

## Evidence

- **issue_error_log:** 用户报告 go_plugin.LOG 持续报错 flusher_http.go:437 unsupported event type 3，证实 v2 架构下转换器未处理该事件类型导致数据丢弃。
- **epic_tracking:** Epic #2595 阶段 2 明确列出 B4/B5 待办项（Processor 迁移 + flusher v2 适配、CI lint 禁止仅假定 Events[0] 为 Log），表明该兼容性缺口为已知架构演进任务。
- **pr_2620_context:** 已合并的 PR #2620 (A1) 仅重构配置解析黑名单，正文声明不保证运行时数据可达，与本 Issue 报告的运行时转换失败现象一致，确认非配置解析问题而是运行时插件适配缺口。
