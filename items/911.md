## Summary

本 Issue 请求为采集任务（Pipeline）增加运行时暂停与恢复能力，属于核心控制面状态机增强需求。当前主线代码的任务生命周期仍由配置加载/卸载（Start/Stop/Reload）驱动，尚未提供独立的 Pause/Resume 接口或无损状态冻结机制。该需求明确且无法通过插件系统旁路实现，需核心架构设计支持，故保持开启。

## Best Possible Solution

保持开启。建议维护者或贡献者补充详细设计方案（RFC），明确暂停/恢复的触发入口（如动态配置标记、REST API 或系统信号）、状态机转换边界、Buffer/Checkpoint 保留策略及恢复时的 Offset 衔接逻辑。可先行评估现有 Stop/Start 配合磁盘 Checkpoint 的启停机制是否已满足业务容错需求；若需轻量级无损暂停，则需作为 Pipeline 控制面新特性纳入核心开发路线。

## Evidence

- **core_lifecycle_analysis:** 当前 Pipeline 生命周期管理主要依赖配置热更新实现启停（Start/Stop/Reload），主线代码中未见独立的 Pause/Resume 接口与运行时状态冻结逻辑。暂停需求涉及核心调度与缓冲策略改造，尚未实现。
