## Summary

本 Issue 请求为采集任务（Pipeline）增加运行时暂停与恢复能力，属于核心控制面状态机增强需求。经核查当前 main 分支，任务生命周期仍由配置加载/卸载（Start/Stop/Reload）驱动，尚未提供独立的 Pause/Resume 接口或无损状态冻结机制。该需求明确且无法通过插件系统旁路实现，无关联 PR 或重复工单，故保持开启以待核心架构设计或排期。

## Best Possible Solution

保持开启。建议维护者或贡献者补充详细设计方案（RFC），明确暂停/恢复的触发入口（如动态配置标记、REST API 或系统信号）、状态机转换边界、Buffer/Checkpoint 保留策略及恢复时的 Offset 衔接逻辑。可先行评估现有 Stop/Start 配合磁盘 Checkpoint 的启停机制是否已满足业务容错需求；若需轻量级无损暂停，则需作为 Pipeline 控制面新特性纳入核心开发路线。
