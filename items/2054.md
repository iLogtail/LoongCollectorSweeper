## Summary

本 PR 提议增强 Encoder 接口以支持动态变量键解析（如 %{metadata.xxx}）与缓冲回收，具有明确的产品价值，可与 Converter 行为对齐。但 PR 涉及核心接口破坏性变更（EncoderV1/V2 签名修改），目前仅完成 Prometheus Encoder 与 HTTP Flusher 的局部适配，直接合并将导致仓库内其他 Encoder 实现编译中断。此外 PR 基线已过时并存在合并冲突。鉴于该特性对动态路由与 Flusher 配置有实际意义，且属于可挽救的核心 API 演进工作，不符合自动关闭条件，建议保持开启。

## Best Possible Solution

建议作者或贡献者 Rebase 至最新 main 分支解决冲突；全量适配仓库内所有 EncoderV1/V2 实现类与调用方以修复编译中断；维护者介入评估破坏性变更的兼容性策略（如提供默认实现、向后兼容包装或分阶段迁移）；补充完整单元与集成测试后重新请求 Review。若长期无更新，维护者可考虑提取核心设计思路另起 PR 推进。
