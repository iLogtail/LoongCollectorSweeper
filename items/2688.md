## Summary

本 Issue 报告了在使用 flusher_kafka_v2 时，因发送阻塞引发背压导致 Aggregator 队列满（loggroup queue is full），进而使整个采集流水线卡死的有效缺陷。当前 main 分支未见针对该 Kafka 阻塞死锁或背压丢弃策略的明确修复，且报告提供了完整配置与日志，属于需维护者深入排查的核心流控问题，故保持开启。

## Best Possible Solution

建议维护者或贡献者跟进：1. 请用户提供卡死时的 goroutine dump 或 pprof 数据以精确定位阻塞调用栈；2. 审查 flusher_kafka_v2 的发送超时、重试及异步实现，评估是否需引入非阻塞发送、队列满丢弃/降级策略或可配置的超时参数；3. 检查 Aggregator/PluginRunner 层的背压传导机制，确认队列满时的预期行为与死锁防护；4. 建议用户先升级至最新稳定版 v3.3.5 并调整 Kafka flusher 的缓冲/超时参数验证是否缓解。

## Evidence

- **issue_report:** 用户提供 v3.1.4 环境下的完整 YAML 配置与连续触发的 AGGREGATOR_ADD_ALARM 日志，明确指出 flusher_kafka_v2 发送阻塞导致流水线卡死，复现路径清晰。
- **code_analysis:** 当前 main 分支的 plugin_runner_v1.go 与 Aggregator 队列流控逻辑中，未见针对 flusher_kafka_v2 阻塞导致背压死锁的明确修复或超时/丢弃策略变更。该问题涉及核心管道流控与外部组件交互，需维护者进一步审查。
