## Summary

本 PR 尝试修复 RFC3164 syslog 解析中 TAG 字段未限制长度可能导致的数组越界问题，方向正确且符合 RFC 规范。但修改直接作用于 external/ 目录下的 vendored 第三方库副本，且未补充对应的单元测试。涉及第三方依赖维护策略（Go Modules 与本地补丁的取舍）及测试覆盖缺失，需维护者介入评估依赖管理方式并要求完善测试后再行合并。

## Best Possible Solution

建议维护者确认 external/ 目录下第三方库的维护策略。若项目已全面使用 Go Modules，应引导作者向上游 jeromer/syslogparser 提交修复，并通过更新 go.mod 引入；若仍需本地维护 vendored 副本，请作者补充针对 TAG 长度超限（>32字符）及边界条件的单元测试，验证解析逻辑未破坏现有合法日志格式。待测试覆盖完善且依赖策略确认后，由维护者重新审查合并。
