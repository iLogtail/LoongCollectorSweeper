## Summary

本 Issue 请求在单进程内支持采集任务分级保障（QoS/优先级调度），属于核心调度与资源管理架构演进范畴。当前 main 分支未原生实现该能力，且无法通过插件系统独立承载。社区提出的多进程+cgroups 方案为有效运维变通，但未满足单进程原生分级诉求。需求清晰合理，需维护者进行核心路线评估，故保持开启。

## Best Possible Solution

保持开启以待维护者评估核心调度器与资源管理架构路线。若纳入规划，需在 Pipeline/Config 层设计 priority/qos 字段及对应的资源隔离与降级策略；若暂不纳入核心路线，建议将社区提出的多实例配合 cgroups/systemd 的分级隔离方案沉淀至官方最佳实践文档，并在此 Issue 中说明后续规划。

## Evidence

- **core_feature_gap:** 当前 main 分支 Pipeline 调度与并发控制逻辑中未发现基于任务优先级的资源抢占或降级队列实现，配置结构亦无 priority/qos 字段。
