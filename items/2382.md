## Summary

本 PR 旨在为 metric input 与 aggregator 添加 panic 自动重启机制，需求合理且代码变更集中。但当前实现存在架构缺陷（在 defer recover 中通过 cc.Run 递归触发重试，无最大重试次数与退避策略，可能导致 goroutine 泄漏或栈溢出），且基线陈旧存在合并冲突。功能具有核心价值，需重构后继续推进，故保持开启。

## Best Possible Solution

建议作者或维护者先将分支 rebase 至最新 main 解决冲突。将 panic 重启逻辑重构为带最大重试次数限制与指数退避的安全调度机制（例如在外部控制循环或独立 goroutine 中接管生命周期与重试，而非在 defer recover 回调中直接递归调用），补充边界测试与重试配置说明后，请求维护者复审。
