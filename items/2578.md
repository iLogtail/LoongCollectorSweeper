## Summary

本 Issue 详细报告了 flusher_otlp 向 OTLP gRPC 后端转发 Trace 失败的问题，已提供完整的交叉验证链路与配置细节。核心疑点在于 gRPC 明文传输配置（如 Insecure 参数）缺失、Endpoint 协议前缀兼容性，以及连接失败时缺乏有效错误日志。属于有效的配置疑问与潜在可用性/文档缺陷，需维护者或插件贡献者核实默认行为并给出明确配置指引。

## Best Possible Solution

建议维护者或 OTLP 插件贡献者核查 flusher_otlp 的 gRPC 客户端初始化逻辑与配置文档：1. 明确向 4317 端口发送明文 gRPC 时是否需显式配置 Insecure: true 或调整 Endpoint 格式（如移除 http:// 前缀）；2. 检查连接或导出失败时的日志级别，避免静默丢弃；3. 在 Issue 中回复正确的配置示例邀请用户验证。待配置方案明确、文档更新或静默失败问题修复后关闭。

## Evidence

- **config_gap:** 用户配置中未显式声明 gRPC 明文传输参数（如 Insecure: true），且 Endpoint 带有 http:// 前缀，可能与底层 gRPC Dialer 的默认 TLS 行为或协议解析冲突，导致连接静默失败。需维护者确认插件默认行为与正确配置范式。
