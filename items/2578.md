## Summary

本 Issue 报告了 flusher_otlp 向 OTLP gRPC 后端转发 Trace 失败的问题，提供了详尽的交叉验证链路与配置。经核查当前 main 分支代码，flusher_otlp 的 gRPC 客户端初始化对 Endpoint 协议前缀（http/https）与 Insecure 参数的处理逻辑仍存在配置门槛，且连接失败时日志输出可能不足。该问题属于有效的配置疑问与潜在可用性/文档缺陷，需维护者或插件贡献者核实默认行为、补充配置指引或优化错误日志。目前无明确修复 PR 合并，证据不足以关闭。

## Best Possible Solution

建议维护者或 OTLP 插件贡献者核查 flusher_otlp 的 gRPC 客户端初始化逻辑与配置文档：1. 明确向 4317 端口发送明文 gRPC 时是否需显式配置 Insecure: true 或调整 Endpoint 格式（如移除 http:// 前缀）；2. 检查连接或导出失败时的日志级别，避免静默丢弃；3. 在 Issue 中回复正确的配置示例邀请用户验证。待配置方案明确、文档更新或静默失败问题修复后关闭。
