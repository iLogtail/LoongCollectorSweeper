## Summary

本 Issue 详细报告了 flusher_otlp 向 OTLP gRPC 后端转发 Trace 失败的问题，已提供完整的 Docker Compose 环境与四条交叉验证链路，明确排除了网络与下游后端故障。核心疑点在于 gRPC 明文传输配置（如 Insecure 参数）缺失、Endpoint 协议解析兼容性，以及连接失败时缺乏有效错误日志。属于有效的配置疑问与潜在可用性缺陷，需维护者核实插件默认行为、明确配置方案并补充文档或修复静默失败逻辑。

## Best Possible Solution

建议维护者或 OTLP 插件贡献者核查 flusher_otlp 的 gRPC 客户端初始化逻辑与配置文档：1. 明确向 4317 端口发送明文 gRPC 时是否需显式配置 Insecure: true 或调整 Endpoint 格式（如移除 http:// 前缀）；2. 检查连接或导出失败时的日志级别，避免静默丢弃；3. 在 Issue 中回复正确的配置示例邀请用户验证。待配置方案明确、文档更新或静默失败问题修复后关闭。
